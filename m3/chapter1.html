大數據生態系統

大數據生態系統 (Big Data Ecosystem) 包含了一系列用於處理海量數據的工具和技術。這些技術旨在解決傳統資料庫無法處理的 “3V” 問題：Volume (大量)、Velocity (高速)、Variety (多樣)。

分散式運算框架

分散式運算框架 (Distributed Computing Frameworks) 是大數據處理的核心，解決了單機無法處理大規模數據的問題。

Hadoop

Hadoop 是一個開源框架，允許使用簡單的程式設計模型跨計算機叢集分散式處理大數據。它主要由三個核心組件組成：

  1. HDFS (Hadoop Distributed File System)：
    • NameNode：主節點，負責管理文件系統的元數據 (Metadata)，如文件名、目錄結構、文件屬性等。
    • DataNode：工作節點，負責實際存儲數據塊 (Blocks)。
  2. YARN (Yet Another Resource Negotiator)：
    • 負責叢集資源的管理和調度。
    • ResourceManager：全局資源管理器。
    • NodeManager：單個節點的資源管理器。
  3. MapReduce：
    • Hadoop 的核心運算模型，分為 Map（映射）和 Reduce（歸約）兩個階段。
    • 適合批次處理，但磁碟 I/O 頻繁，速度較慢。

Spark

Spark 提供了更快速的記憶體內運算 (In-Memory Computing) 能力，比 Hadoop MapReduce 快 100 倍。

  • 核心概念：
    • RDD (Resilient Distributed Dataset)：Spark 的基本數據結構，具有彈性（可恢復）和分散式特性。
    • 惰性求值 (Lazy Evaluation)：Transformation 操作（如 map, filter）不會立即執行，只有遇到 Action 操作（如 count, collect）時才會真正觸發計算。
  • Spark 生態系統：
    • Spark SQL：用於處理結構化數據，支持 SQL 查詢。
    • Spark Streaming：用於即時數據流處理。
    • MLlib：機器學習庫。
    • GraphX：圖形計算庫。
  • DataFrame：類似於關聯式資料庫的表格，提供了更高級的 API，並經過 Catalyst 優化器優化。

Python 範例：使用 PySpark 進行字數統計

# 假設已安裝 pyspark
from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("WordCount").getOrCreate()

# 創建一個簡單的 DataFrame
data = [("Hello world",), ("Hello Spark",), ("Big Data",)]
df = spark.createDataFrame(data, ["text"])

# 拆分單詞並計數
from pyspark.sql.functions import explode, split, col

words = df.select(explode(split(col("text"), " ")).alias("word"))
word_counts = words.groupBy("word").count()

word_counts.show()
spark.stop()

儲存解決方案

有效的儲存解決方案 (Storage Solutions) 是管理大數據的基礎。

HDFS

Hadoop 分散式檔案系統 (HDFS, Hadoop Distributed File System) 將大文件分割成區塊 (Blocks, 預設 128MB)，並複製到多個節點上（預設 3 份）以確保可靠性。這使得 HDFS 能夠在廉價的硬體上運行並容忍硬體故障。

關聯式資料庫與 ACID (RDBMS & ACID)

傳統的關聯式資料庫 (RDBMS) 如 MySQL, PostgreSQL 強調數據的一致性與可靠性，這主要通過 ACID 原則來保證：

  • Atomicity (原子性)：交易 (Transaction) 中的所有操作要麼全部成功，要麼全部失敗 (All-or-Nothing)。
  • Consistency (一致性)：交易完成後，數據必須從一個有效狀態轉變為另一個有效狀態，符合所有定義的規則（如約束）。
  • Isolation (隔離性)：多個並發交易之間互不干擾，一個交易的中間狀態對其他交易不可見。
  • Durability (持久性)：一旦交易提交 (Commit)，其結果就是永久性的，即使系統崩潰也不會丟失。

雖然 ACID 保證了數據的高度可靠性，但在大規模分散式環境下，為了追求高可用性 (Availability) 和分區容錯性 (Partition Tolerance)，NoSQL 資料庫往往會犧牲部分一致性 (Consistency)，遵循 BASE 模型 (Basically Available, Soft state, Eventual consistency)。

CAP 定理 (CAP Theorem)

CAP 定理指出，對於一個分散式計算系統，不可能同時滿足以下三點：

  • Consistency (一致性)：所有節點在同一時間具有相同的數據。
  • Availability (可用性)：保證每個請求都能得到響應（無論成功或失敗）。
  • Partition Tolerance (分區容錯性)：系統在任意訊息丟失或失敗的情況下仍能繼續運行。

在分散式系統中，P (分區容錯性) 通常是必須的，因此我們只能在 C (一致性) 和 A (可用性) 之間做權衡：

  • CP (Consistency + Partition Tolerance)：如 HBase, MongoDB。犧牲可用性，確保數據一致。
  • AP (Availability + Partition Tolerance)：如 Cassandra, DynamoDB。犧牲一致性（接受最終一致性），確保高可用。

NoSQL 資料庫

NoSQL (Not Only SQL) 資料庫適應了非結構化數據的儲存需求，具有高擴展性 (Scalability) 和高性能 (Performance)。

  • 文件型 (Document)：
    • 例子：MongoDB。
    • 特點：儲存 JSON/BSON 格式數據，Schema-free。
    • 適用場景：內容管理系統、目錄、使用者資料。
  • 鍵值對 (Key-Value)：
    • 例子：Redis, DynamoDB。
    • 特點：通過 Key 快速存取 Value，速度極快。
    • 適用場景：快取 (Caching)、Session 管理、購物車。
  • 列式 (Column-family)：
    • 例子：Cassandra, HBase。
    • 特點：按列存儲，適合寫入密集型和大規模數據查詢。
    • 適用場景：日誌記錄、時間序列數據、物聯網 (IoT)。
  • 圖形 (Graph)：
    • 例子：Neo4j。
    • 特點：存儲節點和邊，擅長處理複雜關係。
    • 適用場景：社交網絡、推薦引擎、詐欺檢測。

大數據儲存格式 (Big Data Storage Formats)

選擇合適的檔案格式對大數據處理的效能至關重要。

  • 行式儲存 (Row-based)：
    • CSV/JSON：文字格式，易讀但佔用空間大，解析慢。
    • Avro：二進位格式，Schema 隨數據存儲。適合大量寫入操作（如 Kafka 消息）。
  • 列式儲存 (Columnar)：
    • Parquet：二進位列式儲存，支持高效壓縮和編碼。適合 OLAP 分析查詢（只讀取需要的列）。
    • ORC (Optimized Row Columnar)：高度優化的列式儲存，通常與 Hive 配合使用，壓縮比極高。

資料湖

資料湖 (Data Lakes) 允許以原生格式儲存大量結構化和非結構化數據，通常基於物件儲存（如 AWS S3, Azure Blob Storage）。

資料湖 vs 資料倉儲 (Data Warehouse)：

特性 資料湖 (Data Lake) 資料倉儲 (Data Warehouse)
數據類型 結構化、半結構化、非結構化 (Raw Data) 結構化 (Processed Data)
Schema Schema-on-Read (讀取時定義) Schema-on-Write (寫入時定義)
成本 低 (廉價存儲) 高 (高性能存儲)
使用者 資料科學家、資料工程師 商業分析師 (BI)
靈活性 高，適合探索性分析 低，適合固定報表
