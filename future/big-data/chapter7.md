# 第 7 章：大數據系統與架構

處理海量數據需要分散式系統與高效能架構的支援。

## 7.1 資料庫特性 (ACID)

關聯式資料庫 (RDBMS) 強調 ACID 特性：

*   **原子性 (Atomicity)**：交易不可分割，需**完全成功或完全失敗** (C)。若交易中斷，需進行 Rollback (A)。
*   **一致性 (Consistency)**：交易前後資料需符合完整性規則。
*   **隔離性 (Isolation)**：多筆交易並發執行時互不干擾。
*   **持久性 (Durability)**：交易一旦提交，結果永久保存。

## 7.2 大數據處理架構

### 7.2.1 即時資料分析

*   **IoT 應用**：監控大量裝置異常行為，需結合**大數據平台 + 即時資料分析技術** (C)。
*   **流式處理 (Stream Processing)**：
    *   架構：感測器 $\rightarrow$ 邊緣運算/Broker $\rightarrow$ **流式處理框架** (如 Kafka, Flink) $\rightarrow$ 資料湖/推論 (C)。
    *   目的：在毫秒級回應異常事件。

### 7.2.2 批次與分散式處理

*   **資料湖 (Data Lake)**：儲存結構化與非結構化 (文字、影像) 資料。
*   **分散式計算**：使用 **Apache Spark** 或 Ray 進行分散式預處理與特徵抽取，適合處理多樣化資料來源 (A)。
*   **近似演算法**：
    *   **近似分位數 (Approximate Quantile)**：在極大資料量下，為兼顧效率，在可容忍誤差範圍內**快速估算**分位值 (D)。

## 7.3 圖形資料庫 (Graph Database)

*   **建模設計**：
    *   若需記錄「按讚」行為的時間與裝置，且保留使用者與貼文關係。
    *   **最佳解**：將「按讚」資訊作為**邊的屬性 (Property)** 儲存 (B)。
*   **知識圖譜 (Knowledge Graph)**：
    *   整合異質資料並支援推理。
    *   **RDF (Resource Description Framework)**：以 **Subject - Predicate - Object** 三元組結構建構，具備良好的語意擴展性 (B)。
