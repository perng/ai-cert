# 第二章：NLP 進階應用與 RAG

本章將介紹自然語言處理的實際應用場景，包括情感分析、序列生成任務，以及檢索增強生成 (RAG) 技術。

## 1. 情感分析 (Sentiment Analysis)

情感分析 (Sentiment Analysis) 是 NLP 中最常見且商業價值極高的應用之一。

*   **核心目的**：主要用於**判斷文本中所表達的情感傾向**（如正面、負面、中性）。
*   **商業應用**：
    *   **電商監控**：企業可利用此技術分析顧客在社群平台與商品評論中的文字內容，即時掌握顧客對產品的滿意度變化。
    *   **輿情分析**：品牌監控社群媒體上的討論聲量與情緒。
*   **偏差與挑戰**：
    *   **現象**：模型在面對不同語言或文化背景的評論時，可能會出現判斷不一致的情況。例如，某些文化中習慣用「禮貌但含蓄」的方式表達批評，模型可能誤判為中性或正面。
    *   **原因**：若訓練語料偏向特定文化或語氣特徵（例如只用美國的 Twitter 資料訓練），模型容易產生**內隱偏誤 (Implicit Bias)**。這通常源自於訓練資料來源的不平衡。

## 2. 序列到序列模型 (Seq2Seq)

Seq2Seq (Sequence-to-Sequence) 模型是處理輸入與輸出長度不固定任務的標準架構，通常由編碼器 (Encoder) 與解碼器 (Decoder) 組成。

*   **適用情境**：最適合將輸入文字轉換成**語意等價的另一段文字**。
*   **典型應用**：
    *   **機器翻譯**：將英文句子（長度 N）轉換為中文句子（長度 M）。
    *   **摘要生成**：將長篇文章轉換為短摘要。
    *   **對話系統 (Chatbot)**：根據輸入語句生成回應。
*   **不適合的場景**：
    *   **關鍵字統計**：這是統計任務，不需要 Seq2Seq。
    *   **實體辨識 (NER)**：這是序列標註任務 (Sequence Labeling)，輸入輸出長度通常是一對一對應的。

## 3. 低資源語言處理

對於語料稀缺的語言（Low-resource Languages，如少數民族語言），訓練高效能模型是一大挑戰。

*   **過擬合問題**：由於資料量少（例如僅有 1 萬筆），模型容易死記硬背（過擬合），泛化能力差。
*   **解決策略：反向翻譯 (Back-Translation)**
    *   **概念**：這是一種非常有效的半監督式資料增強技術。
    *   **流程**：
        1.  訓練一個初步的「中文 -> 英文」翻譯模型。
        2.  找大量的**單語英文語料**（這很容易取得）。
        3.  用模型將這些英文翻譯回中文，產生「偽中文」。
        4.  將「偽中文」與「真英文」配對，形成大量的**偽平行語料 (Pseudo-Parallel Corpus)**。
        5.  將這些新資料加入訓練集，重新訓練「英文 -> 中文」模型。
    *   **效益**：在不新增真實人工標註資料的前提下，大幅擴充訓練集並提升泛化能力。

## 4. 檢索增強生成 (RAG)

RAG (Retrieval-Augmented Generation) 結合了檢索系統與生成模型，解決了 LLM 知識過時與幻覺問題。

### 檢索階段的關鍵挑戰

建立高效能 RAG 系統時，檢索階段面臨的最大挑戰往往是**語意相似但意圖不符**。

*   **問題**：向量檢索 (Vector Search) 依賴語意相似度 (Cosine Similarity)。
    *   **情境**：使用者問「如何**刪除**帳號？」。
    *   **檢索結果**：可能會找到「如何**註冊**帳號？」的文件，因為「刪除」與「註冊」在語意空間中可能很近（都是帳號操作），且文件內容高度重疊。
    *   **結果**：雖然語意相似，但**查詢意圖 (Query Intent)** 完全相反。
*   **影響**：這會導致生成模型接收到不相關的上下文，進而產生錯誤的回答（例如教使用者如何註冊，當他想刪除時）。
*   **解決**：優化檢索排序（Re-ranking）與意圖識別是 RAG 的進階課題，不能只依賴向量相似度。

> **範例：向量檢索的陷阱**
>
> 假設我們用餘弦相似度 (Cosine Similarity) 來檢索：
> *   **Query**: "How to **delete** my account?"
> *   **Doc A**: "Guide to **create** an account." (Similarity: 0.85)
> *   **Doc B**: "Steps to **remove** your profile." (Similarity: 0.82)
>
> 雖然 Doc B 才是正確答案，但因為 "create" 和 "account" 這些詞在語料庫中常一起出現，Doc A 的向量可能跟 Query 更近。這就是為什麼單純靠向量檢索有時會失敗。
