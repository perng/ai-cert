AI 導入評估與可行性研究

在 AI 專案啟動前，進行可行性研究的主要目的是？
#4101
  1. 為了趕上科技潮流 (Follow Trends)
  2. 為了消耗預算 (Spend Budget)
  3. 確保專案能解決實際問題並具備技術與經濟可行性 (Ensure Feasibility & Problem Solving)
  4. 為了招聘更多員工 (Hire More Staff)
💡 盲目導入 AI 往往導致失敗。可行性研究能確認需求、技術能力與成本效益，是「謀定而後動」的關鍵。
chap-m2-ch1 sec-feasibility
在需求分析中，「痛點 (Pain Points)」通常指什麼？
#4102
  1. 組織流程中的瓶頸、重複性工作或決策困難 (Process Bottlenecks & Repetitive Work)
  2. 硬體設備的故障 (Hardware Failure)
  3. 軟體的 Bug (Software Bugs)
  4. 員工的身體疼痛 (Physical Pain)
💡 痛點是指組織運作中效率低落、成本高昂或無法滿足客戶需求的地方，正是 AI 可以發揮價值之處。

評估「技術可行性」時，關於資料品質的考量不包括？
#4103
  1. 資料的儲存成本 (Storage Cost)
  2. 資料的代表性 (Representativeness)
  3. 資料的標註品質 (Labeling Quality)
  4. 資料的完整性 (Completeness)
💡 儲存成本屬於「成本效益評估」，而非資料本身的品質或技術可行性問題。

投資報酬率 (ROI) 的計算公式是？
#4104
  1. 投資回報 / 投資成本 (Return / Cost)
  2. 投資成本 / 投資回報 (Cost / Return)
  3. (投資回報 - 投資成本) / 投資成本 (Net Return / Cost)
  4. (投資回報 + 投資成本) / 投資成本 (Total Return / Cost)
💡 ROI 衡量每單位投資帶來的淨利潤，公式為 (淨回報 / 成本) * 100%。

概念驗證 (POC) 的主要目的是？
#4105
  1. 訓練所有員工 (Train All Staff)
  2. 在最小風險下驗證技術可行性與商業價值 (Validate Feasibility & Value with Min Risk)
  3. 完成最終產品開發 (Complete Product Development)
  4. 進行大規模推廣 (Large-scale Rollout)
💡 POC 是小規模的實驗，旨在快速驗證想法是否可行，以決定是否值得投入更多資源進行全面開發。

淨現值 (NPV) 為正代表什麼？
#4116
  1. 專案不需要資金 (No Funding Needed)
  2. 專案風險很高 (High Risk)
  3. 專案會虧損 (Project Loss)
  4. 專案具投資價值，預期回報高於成本 (Positive Investment Value)
💡 NPV 將未來現金流折現回當前價值。NPV > 0 表示考慮時間價值後，專案仍能獲利。

「回收期 (Payback Period)」越短，通常代表？
#4121
  1. 專案越複雜 (More Complex Project)
  2. 資金流動性越好，投資回收越快 (Better Liquidity & Faster Return)
  3. 投資風險越高 (Higher Investment Risk)
  4. 效益越低 (Lower Benefit)
💡 回收期短意味著企業能更快拿回本金，降低了資金被長期佔用的風險。

#4126
  1. 人臉辨識 (Face Recognition)
  2. 銷售量預測 (基於歷史報表) (Sales Prediction)
  3. 文章摘要生成 (Text Summarization)
  4. 語音轉文字 (Speech to Text)
💡 銷售報表是典型的表格數據（結構化數據），適合用機器學習模型進行回歸預測。其他選項多為非結構化數據。

#4131
  1. 系統部署 (System Deployment)
  2. 需求分析 (Requirement Analysis)
  3. 維運監控 (Operation Monitoring)
  4. 模型訓練 (Model Training)
💡 需求分析階段需釐清現狀問題與未來目標，兩者之間的差距就是專案要解決的範圍。

評估資料「代表性 (Representativeness)」是為了避免？
#4136
  1. 儲存空間不足 (Insufficient Storage)
  2. 計算速度太慢 (Slow Computation)
  3. 取樣偏差 (Sampling Bias)
  4. 資料過多 (Too Much Data)
💡 若訓練資料無法代表真實世界的狀況（例如只用夏天的數據訓練銷量預測模型），模型在實際應用（冬天）時就會失效。

  2. 系統整合與推論延遲 (Latency) (System Integration & Latency)

情境：為了趕在年底前上線，PM 決定跳過 POC 直接進行全面開發。這最可能導致什麼後果？
#4152
  1. 在投入大量資源後才發現技術不可行或不符需求 (High Risk of Failure)
  2. 團隊士氣大增 (Boost Morale)
  3. 節省大量成本 (Save Cost)
  4. 專案提早成功 (Early Success)
💡 POC 的目的就是「以小博大」，用最小成本驗證可行性。跳過 POC 等於在未經驗證的情況下進行豪賭，風險極高。

#4164
  1. 終止或重新評估，因為 ROI 過低 (Terminate or Re-evaluate)
  2. 解雇檢測員 (Fire Inspectors)
  3. 更換所有硬體 (Replace Hardware)
  4. 立即導入，因為準確率提升了 (Deploy Immediately)
💡 雖然技術指標提升，但若提升幅度微小且成本極高（邊際效益遞減），導致 ROI 不佳，則不具備商業可行性。
