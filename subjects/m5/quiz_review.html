AI 代理人基礎概念

從聊天到行動：為什麼需要 AI 代理人

AI 代理人（AI Agent）與傳統聊天機器人最主要的差異是什麼？
#7101
  1. 代理人不需要大型語言模型作為其核心運作引擎
  2. 代理人無法理解使用者輸入的自然語言指令
  3. 代理人只能被動回答問題，無法執行動作
  4. 代理人能夠自主進行多步驟規劃與工具呼叫，而聊天機器人主要進行單輪問答
💡 AI 代理人的核心特徵是自主性、多步驟執行與工具使用能力，能主動規劃並執行任務，而非僅被動回應。
chap-m5-ch1 sec-agent-definition
下列哪一項「不是」AI 代理人的核心特徵？
#7102
  1. 自主性 (Autonomy)：無需持續人工干預即可獨立運作
  2. 固定性 (Fixedness)：行為模式在部署後不會改變
  3. 持續性 (Persistence)：能跨多個步驟維持狀態與記憶
  4. 目標導向 (Goal-directed)：圍繞明確目標組織其行為
💡 AI 代理人的特徵包括自主性、感知能力、行動能力、目標導向與持續性。「固定性」並非代理人特徵，代理人能夠動態調整策略。
chap-m5-ch1 sec-agent-definition
相較於一般聊天機器人，AI 代理人最核心的差異是什麼？
#900022
  1. 能根據目標規劃步驟、使用工具並觀察結果後調整行動
  2. 只能回答預先寫好的 FAQ
  3. 必須完全離線執行，不能連接任何外部系統
  4. 只能生成文字，不能處理任務狀態
💡 AI 代理人不只是產生回覆，還會圍繞目標進行規劃、工具調用、狀態追蹤與回饋修正，因此能處理跨步驟任務。

代理人的組成：它由哪些部分構成？

在 AI 代理人的記憶系統中，「向量資料庫（如 Chroma、Pinecone）」屬於哪種記憶類型？
#7103
  1. 長期記憶 (Long-term Memory)，儲存跨任務的知識與經驗
  2. 短期記憶 (Short-term Memory)，儲存當前對話的上下文
  3. 工作記憶 (Working Memory)，儲存當前任務的中間狀態
  4. 感知記憶 (Sensory Memory)，暫存外部環境的輸入
💡 向量資料庫用於儲存長期記憶，能跨任務保存知識與過往經驗，透過語義相似度搜尋進行召回。
chap-m5-ch1 sec-agent-architecture
代理人架構中「短期記憶」主要對應於什麼？
#7109
  1. 外部獨立部署的專屬向量資料庫系統
  2. 大型語言模型的當前對話上下文視窗
  3. 代理人執行腳本中的固定區域變數表
  4. 用來指導代理人行為的核心系統提示詞
💡 短期記憶受限於模型的上下文視窗，保存近期的對話互動。
chap-m5-ch1 sec-agent-architecture
代理人架構中「長期記憶」最常依賴的儲存技術是？
#7110
  1. 系統環境變數與暫存檔案的動態讀寫
  2. 傳統的關聯式資料庫與表格結構儲存
  3. 電腦處理器內建的高速快取記憶體裝置
  4. 透過嵌入模型轉換的向量資料庫系統
💡 向量資料庫能將過往知識轉換為向量，實現跨任務的語意檢索。
chap-m5-ch1 sec-agent-architecture

代理人如何思考和行動：推理迴圈

ReAct (Reasoning + Acting) 框架的核心思想是什麼？
#7104
  1. 使用多個代理人並行執行任務後投票決定結果
  2. 交替進行推理（Thought）和行動（Action），並根據觀察結果動態調整
  3. 透過自我反思記錄失敗原因以改進下次的嘗試
  4. 先產生完整計畫再一次性執行所有規劃的步驟
💡 ReAct 框架的精髓在於「思考-行動-觀察」的交替循環，讓代理人能基於真實的工具回傳結果進行推理，減少幻覺並提高可靠性。
chap-m5-ch1 sec-agent-loop
Reflexion 框架與 ReAct 框架的主要區別是什麼？
#7105
  1. Reflexion 在運作時需要多個 LLM 模型來協同工作
  2. Reflexion 框架只能夠適用於數學計算類型的任務
  3. Reflexion 引入自我反思機制，將失敗經驗以文字形式儲存為記憶以改進後續嘗試
  4. Reflexion 框架在運作時完全不使用工具呼叫
💡 Reflexion 的創新在於讓代理人在任務失敗後生成文字形式的自我反思，並將其作為長期記憶，在後續嘗試中避免重複犯同樣的錯誤。
chap-m5-ch1 sec-agent-loop
在 AI 代理人的框架中，「後設認知 (Metacognition)」的主要作用是什麼？
#7108
  1. 自動為系統中的代理人生成新的工具函數
  2. 用來加速大型語言模型的整體推理速度
  3. 強制代理人按照預先設定的固定腳本執行任務
  4. 讓代理人意識到自身的決策過程，並根據經驗進行自我反省與錯誤修正
💡 後設認知也就是「對思考過程的反思」，讓 AI 代理人能評估自身表現、適應環境並修正錯誤。

代理人的種類

「Agentic RAG」與「Naive RAG」的主要差異是什麼？
#7106
  1. Agentic RAG 的整體回應速度比 Naive RAG 更快
  2. Agentic RAG 只能處理文字資料，而 Naive RAG 可處理多模態資料
  3. Agentic RAG 讓代理人主動決定何時和如何進行檢索，可進行多輪查詢
  4. Agentic RAG 的系統完全不使用向量資料庫
💡 Agentic RAG 將 RAG 融入代理迴圈，代理人能自主判斷何時需要檢索、使用哪種查詢策略，並可多輪迭代查詢以獲得更完整的資訊。
chap-m5-ch1 sec-agent-types
若代理人會先拆解任務、排定步驟，再逐步呼叫搜尋、資料庫與文件工具完成任務，最接近哪一類型？
#900023
  1. 規劃型代理人
  2. 純規則比對代理人
  3. 靜態 FAQ 機器人
  4. 單次分類器
💡 規劃型代理人會把高層目標拆成可執行步驟，並依任務狀態選擇工具與調整流程。
chap-m5-ch1 sec-agent-types
多代理人系統最適合用在哪一種情境？
#900024
  1. 需要研究、撰寫、審查與執行等不同角色分工協作的複雜任務
  2. 只需判斷一個數字是否大於零的簡單規則
  3. 完全不需要溝通或共享狀態的單步驟任務
  4. 不能使用任何工具的純文字改寫任務
💡 多代理人系統適合將複雜任務分配給不同專長角色，例如研究代理、程式代理與審查代理，但也需要協調與衝突管理。

如何評估代理人的好壞

評估 AI 代理人效能時，「步驟效率 (Step Efficiency)」指的是什麼？
#7107
  1. 代理人在給定時間內完成任務的比例
  2. 代理人完成任務所需的最少步驟數，步驟越少效率越高
  3. 代理人在任務中正確選擇工具的比例
  4. 代理人每秒鐘能夠處理的請求總數量
💡 步驟效率衡量代理人解決問題的簡潔程度，不必要的冗餘步驟會降低效率並增加成本和延遲。
chap-m5-ch1 sec-agent-eval
評估 AI 代理人是否可靠時，下列哪一項指標最能反映任務完成品質？
#900025
  1. 在限制時間與權限內正確完成端到端任務的比例
  2. 回覆文字是否總是很長
  3. 模型名稱是否最新
  4. 是否完全不產生日誌
💡 代理人評估應看端到端任務成功率、工具使用正確性、成本、延遲、安全性與可追溯性，而不只是文字流暢度。
chap-m5-ch1 sec-agent-eval
為什麼代理人評估需要紀錄工具呼叫與中間步驟？
#900026
  1. 方便追蹤錯誤來源、檢查權限使用並改善任務流程
  2. 讓代理人輸出更多無關文字
  3. 取代所有測試案例
  4. 避免任何人知道代理人做過什麼
💡 工具呼叫紀錄能支援除錯、稽核、安全檢查與流程優化，尤其在代理人可執行外部動作時更重要。
chap-m5-ch1 sec-agent-eval

代理推理迴圈

Plan-and-Execute 模式在處理任務時的主要優勢是什麼？
#7111
  1. 能夠完全避免模型產生幻覺的錯誤情況
  2. 系統的反應速度快且幾乎沒有任何延遲
  3. 非常適合處理步驟已經明確的固定任務
  4. 整個過程中不需依賴任何外部工具的輔助
💡 該模式將任務一次性拆解為多個步驟，非常適合邏輯清晰且明確的工作。
chap-m5-ch1
Plan-and-Execute 模式在面對何種情況時最容易發生失敗？
#7112
  1. 當任務的內容本身過於簡單且缺乏挑戰時
  2. 系統需要進行多次的工具函數呼叫步驟時
  3. 本地電腦的可用記憶體空間不足夠使用時
  4. 執行過程中環境發生非預期的突發變化時
💡 由於一開始就制定好所有計畫，一旦執行環境有變，系統往往無法彈性調整。
chap-m5-ch1
Reflexion 框架相對於一般迴圈，加入了什麼關鍵機制？
#7115
  1. 任務失敗之後進行自我反省與改進
  2. 完全隨機地嘗試各種可用的新方法
  3. 將複雜任務分配給其他的協作代理
  4. 任務開始之前先進行詳細的步驟規劃
💡 Reflexion 的核心在於遇到失敗時能進行反思，並將經驗保留給後續嘗試。
chap-m5-ch1
在 Reflexion 框架中，代理人自我反省的結果通常會如何被儲存？
#7116
  1. 轉化為長期記憶庫中的歷史經驗紀錄
  2. 直接寫入系統的底層錯誤日誌檔案中
  3. 作為短期記憶區塊中的一次性使用變數
  4. 備份到使用者個人的雲端硬碟儲存空間
💡 反省結果會被存入記憶體中，讓代理人未來面對類似任務時能避開錯誤。
chap-m5-ch1
「後設認知 (Metacognition)」賦予代理人哪一種關鍵能力？
#7117
  1. 自主偵測行為缺陷並主動修正執行錯誤
  2. 能夠自動產生出全新的後端應用程式碼
  3. 繞過底層安全機制以獲取系統最高權限
  4. 產生出更快的文字串流生成速度與效率
💡 後設認知讓代理人能「思考自己的思考過程」，進而達到修正錯誤與適應環境。
chap-m5-ch1
在代理人的推理迴圈中，「Action (行動)」階段的主要作用是？
#7123
  1. 評估自身表現的優劣並將其寫入錯誤日誌
  2. 實際呼叫外部工具或 API 來改變環境狀態
  3. 觀察並記錄環境在指令執行後的回傳結果
  4. 分析使用者輸入文字背後所隱藏的真實意圖
💡 行動階段是指模型決定好策略後，具體執行工具呼叫來影響外部世界。
chap-m5-ch1
在代理人的推理迴圈中，「Observation (觀察)」階段的主要作用是？
#7124
  1. 生成給使用者的最終自然語言對話回覆內容
  2. 將整次對話的完整歷史記錄壓縮備份到雲端
  3. 決定下一步應該要呼叫哪一個外部系統的工具
  4. 獲取並解析外部工具執行後所回傳的具體結果
💡 觀察階段讓代理人能看到剛才行動的結果，作為後續判斷與推理的依據。
chap-m5-ch1
在 ReAct 框架中，Thought（思考）階段後通常緊接著哪一個階段？
#7131
  1. Action（行動）階段
  2. 記憶儲存階段
  3. 任務規劃階段
  4. 最終答案生成階段
💡 ReAct 循環是「思考→行動→觀察→再思考」，思考後緊接行動。
chap-m5-ch1
在 Plan-and-Execute 框架中，如果執行階段遇到非預期狀況，通常如何處理？
#7133
  1. 忽略錯誤並繼續執行原計劃
  2. 退回到規劃階段進行重新規劃
  3. 自動切換到另一組完全不同的工具
  4. 直接將任務標記為失敗
💡 Plan-and-Execute 在遇到問題時可以回到規劃階段動態調整，但不如 ReAct 靈活。
chap-m5-ch1
Reflexion 框架中的自我反思機制主要依賴哪一種技術來產生？
#7136
  1. 使用傳統的程式碼異常處理機制
  2. 使用固定模板自動生成反省文字
  3. 讓語言模型本身以自然語言撰寫反省內容
  4. 透過外部 API 查詢錯誤原因
💡 Reflexion 讓 LLM 用自己的語言描述失敗原因，這種文字形式的反思比結構化記錄更有幫助。
chap-m5-ch1
下列哪一個不是 ReAct 框架的核心步驟？
#7142
  1. Observation（觀察）
  2. Thought（思考）
  3. Reflection（反思）
  4. Action（行動）
💡 Reflection（反思）是 Reflexion 框架的特色，非 ReAct 的核心步驟。ReAct 的核心是思考→行動→觀察。
chap-m5-ch1
在 ReAct 循環中，Observation（觀察）階段的結果對後續思考有何影響？
#7145
  1. 觀察結果會被忽略，模型仍然按原計劃執行
  2. 觀察結果作為新的事實依據，影響下一步的推理與決策
  3. 觀察結果只記錄在日誌中，不影響當次任務
  4. 觀察結果會直接覆寫使用者的原始輸入
💡 觀察結果是下一輪思考的關鍵輸入，讓代理人基於真實回饋動態調整行為。
chap-m5-ch1
下列何種情境最適合使用 Plan-and-Execute 而非 ReAct？
#7147
  1. 需要即時監控多個社群媒體的輿情分析系統
  2. 步驟明確且不太需要中途調整的批次資料處理任務
  3. 需要與使用者多輪對話確認需求的客服機器人
  4. 需要頻繁查詢即時股價的投資顧問
💡 Plan-and-Execute 適合步驟可預先確定的任務，批次資料處理是典型應用。
chap-m5-ch1
Reflexion 框架中，若代理人在多次嘗試後仍失敗，它通常會怎麼做？
#7150
  1. 自動切換到另一個完全不同領域的語言模型
  2. 無限期重試直到成功為止

  4. 用來過濾使用者輸入文字中可能包含的各種不雅詞彙
💡 沙盒限制了程式執行的影響範圍，防止惡意操作破壞主系統。

代理人若擁有撰寫與執行程式碼的能力，最主要的風險在於？
#7529
  1. 可能會意外寫出具有破壞性或被惡意利用的腳本
  2. 會導致作業系統的圖形介面變得非常不穩定與容易當機
  3. 會自動刪除系統中所有不是由 AI 所產生的原始程式碼
  4. 會佔用過多的網路頻寬導致使用者無法正常上網
💡 程式碼執行權限極高，若未加限制，可能對系統造成嚴重危害。

電腦使用代理 (Computer Use Agent) 的運作方式類似於什麼？
#7520
  1. 如同人類般透過視覺辨識螢幕並控制滑鼠與鍵盤
  2. 一個專門用來阻擋惡意軟體入侵的系統防火牆
  3. 一個隱藏在背景負責自動備份資料的批次執行檔
  4. 一個只能夠處理文字指令的傳統聊天機器人系統
💡 這類代理不依賴 API，而是透過像素級視覺與 GUI 直接互動。

未來 AI 代理朝向邊緣計算 (Edge Computing) 發展的主要動機為何？
#7525
  1. 為了讓代理人可以更容易被集中監控與嚴格管理
  2. 為了強迫使用者購買價格更為昂貴的高階硬體設備
  3. 為了讓所有的 AI 模型都能夠被統一部署在同一個地方
  4. 降低對雲端的依賴，提升回應速度與保護本地隱私
💡 邊緣計算將運算推向裝置端，具有低延遲與高隱私的優勢。
