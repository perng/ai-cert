AI 代理人基礎概念

什麼是 AI 代理人

AI 代理人（AI Agent）與傳統聊天機器人最主要的差異是什麼？
#7101
  1. 代理人只能回答問題，不能執行動作
  2. 代理人能夠自主進行多步驟規劃與工具呼叫，而聊天機器人主要進行單輪問答
  3. 代理人不需要大型語言模型作為核心
  4. 代理人無法理解自然語言指令
💡 AI 代理人的核心特徵是自主性、多步驟執行與工具使用能力，能主動規劃並執行任務，而非僅被動回應。
chap-m5-ch1 sec-agent-definition
下列哪一項「不是」AI 代理人的核心特徵？
#7102
  1. 自主性 (Autonomy)：無需持續人工干預即可運作
  2. 目標導向 (Goal-directed)：圍繞明確目標組織行為
  3. 固定性 (Fixedness)：行為模式在部署後不會改變
  4. 持續性 (Persistence)：能跨多個步驟維持狀態與記憶
💡 AI 代理人的特徵包括自主性、感知能力、行動能力、目標導向與持續性。「固定性」並非代理人特徵，代理人能夠動態調整策略。

下列哪一項操作屬於代理人的「感知能力 (Perception)」範疇？
#7113
  1. 規劃出完成任務的詳細後續步驟
  2. 讀取使用者的文字輸入與系統日誌
  3. 呼叫外部 API 執行實際的網路請求
  4. 根據執行結果進行自我反省與修正錯誤
💡 感知能力指的是代理人接收並理解來自外部環境的輸入資訊。

當代理人遇到未曾見過的突發情況時，最重要的展現能力是？
#7121
  1. 直接中斷執行並回報任務失敗給終端使用者
  2. 基於環境回饋來動態調整策略並尋找替代方案
  3. 隨機挑選系統中任何一個可用的工具進行測試
  4. 忽略所有出現的錯誤訊息並繼續執行既定步驟
💡 自主性與適應力是代理人的核心，面對變化時能動態調整是其最大價值。

相較於寫死的傳統自動化腳本，AI 代理人的核心優勢是什麼？
#7122
  1. 執行過程中絕對不會產生任何系統錯誤
  2. 能夠彈性適應高度不可預測的動態環境
  3. 程式執行的總耗時必定比傳統腳本更快
  4. 系統在運作時完全不需要任何人類監督
💡 傳統腳本只能處理預先定義好的狀況，而代理人能根據上下文彈性處理未知變化。

代理人的組成架構

在 AI 代理人的記憶系統中，「向量資料庫（如 Chroma、Pinecone）」屬於哪種記憶類型？
#7103
  1. 短期記憶 (Short-term Memory)，儲存當前對話上下文
  2. 工作記憶 (Working Memory)，儲存當前任務的中間狀態
  3. 長期記憶 (Long-term Memory)，儲存跨任務的知識與經驗
  4. 感知記憶 (Sensory Memory)，暫存外部環境輸入
💡 向量資料庫用於儲存長期記憶，能跨任務保存知識與過往經驗，透過語義相似度搜尋進行召回。
chap-m5-ch1 sec-agent-architecture
代理人架構中「短期記憶」主要對應於什麼？
#7109
  1. 外部獨立部署的專屬向量資料庫系統
  2. 大型語言模型的當前對話上下文視窗
  3. 代理人執行腳本中的固定區域變數表
  4. 用來指導代理人行為的核心系統提示詞
💡 短期記憶受限於模型的上下文視窗，保存近期的對話互動。
chap-m5-ch1 sec-agent-architecture
代理人架構中「長期記憶」最常依賴的儲存技術是？
#7110
  1. 電腦處理器內建的高速快取記憶體
  2. 透過嵌入模型轉換的向量資料庫系統
  3. 傳統的關聯式資料庫與表格結構儲存
  4. 系統環境變數與暫存檔案的動態讀寫
💡 向量資料庫能將過往知識轉換為向量，實現跨任務的語意檢索。
chap-m5-ch1 sec-agent-architecture
AI 代理人設定中的「Persona (角色設定)」主要目的是什麼？
#7114
  1. 強制限制模型執行的最高運算速度
  2. 賦予模型特定的行為邊界與互動風格
  3. 決定系統預設需要掛載多少工具數量
  4. 自動減少每次對話的上下文視窗大小
💡 角色設定能指導代理人該以何種語氣和態度回應，確保行為符合預期。
chap-m5-ch1
下列何者最符合「工作記憶 (Working Memory)」的典型應用場景？
#7125
  1. 永遠記住使用者的名字與偏好語言設定
  2. 暫存多步驟計算過程中產生的中間變數
  3. 永久保存過去所有專案任務的歷史經驗
  4. 記錄系統啟動時載入的預設系統提示詞
💡 工作記憶就像系統的草稿紙，專門用來暫存執行中任務的各種中間狀態。
chap-m5-ch1
下列哪一個選項「不屬於」現代 AI 代理人的核心組成要素？
#7127
  1. 具備自然語言理解能力的大型語言模型
  2. 只能按照單一路徑執行的固定不變決策樹
  3. 能夠用來影響外部環境的可呼叫外部工具
  4. 用來儲存任務狀態與歷史經驗的記憶系統
💡 代理人依賴 LLM 動態推理，而非傳統自動化系統所使用的固定決策樹。
chap-m5-ch1
為什麼功能完善的 AI 代理人系統不可或缺「長期記憶」？
#7128
  1. 為了讓模型能以更快的速度生成文字對話串流
  2. 為了在跨越多個獨立對話時仍能保留過往經驗
  3. 為了大幅度減少系統呼叫外部 API 的整體次數
  4. 為了能直接取代大型語言模型本身的內部權重
💡 長期記憶讓代理人能記住使用者的偏好與過往互動，提供更個人化的服務。

代理推理迴圈

ReAct (Reasoning + Acting) 框架的核心思想是什麼？
#7104
  1. 先生成完整計劃再一次性執行所有步驟
  2. 透過自我反思記錄失敗原因以改進下次嘗試
  3. 交替進行推理（Thought）和行動（Action），並根據觀察結果動態調整
  4. 使用多個代理人並行執行任務後投票決定結果
💡 ReAct 框架的精髓在於「思考-行動-觀察」的交替循環，讓代理人能基於真實的工具回傳結果進行推理，減少幻覺並提高可靠性。
chap-m5-ch1 sec-agent-loop
Reflexion 框架與 ReAct 框架的主要區別是什麼？
#7105
  1. Reflexion 不使用工具呼叫
  2. Reflexion 引入自我反思機制，將失敗經驗以文字形式儲存為記憶以改進後續嘗試
  3. Reflexion 只適用於數學計算任務
  4. Reflexion 需要多個 LLM 模型協同工作
💡 Reflexion 的創新在於讓代理人在任務失敗後生成文字形式的自我反思，並將其作為長期記憶，在後續嘗試中避免重複犯同樣的錯誤。
chap-m5-ch1 sec-agent-loop
在 AI 代理人的框架中，「後設認知 (Metacognition)」的主要作用是什麼？
#7108
  1. 加速大型語言模型的推理速度
  2. 讓代理人意識到自身的決策過程，並根據經驗進行自我反省與錯誤修正
  3. 強制代理人按照固定腳本執行任務
  4. 自動為代理人生成新的工具函數
💡 後設認知也就是「對思考過程的反思」，讓 AI 代理人能評估自身表現、適應環境並修正錯誤。

Plan-and-Execute 模式在處理任務時的主要優勢是什麼？
#7111
  1. 反應速度極快且無延遲
  2. 適合處理步驟明確的任務
  3. 不需依賴外部工具的輔助
  4. 能夠完全避免模型產生幻覺
💡 該模式將任務一次性拆解為多個步驟，非常適合邏輯清晰且明確的工作。
chap-m5-ch1
Plan-and-Execute 模式在面對何種情況時最容易發生失敗？
#7112
  1. 任務內容過於簡單且缺乏挑戰
  2. 執行過程中環境發生突發的變化
  3. 系統需要進行多次的工具函數呼叫
  4. 本地電腦的可用記憶體空間不足時
💡 由於一開始就制定好所有計畫，一旦執行環境有變，系統往往無法彈性調整。
chap-m5-ch1
Reflexion 框架相對於一般迴圈，加入了什麼關鍵機制？
#7115
  1. 任務開始前的詳細步驟規劃
  2. 任務失敗後的自我反省與改進
  3. 將複雜任務分配給其他協作代理
  4. 完全隨機地嘗試各種可用的新方法
💡 Reflexion 的核心在於遇到失敗時能進行反思，並將經驗保留給後續嘗試。
chap-m5-ch1
在 Reflexion 框架中，代理人自我反省的結果通常會如何被儲存？
#7116
  1. 作為短期記憶區塊中的一次性變數
  2. 轉化為長期記憶庫中的歷史經驗紀錄
  3. 直接寫入系統的底層錯誤日誌檔案中
  4. 備份到使用者個人的雲端硬碟儲存空間
💡 反省結果會被存入記憶體中，讓代理人未來面對類似任務時能避開錯誤。
chap-m5-ch1
「後設認知 (Metacognition)」賦予代理人哪一種關鍵能力？
#7117
  1. 產生出更快的文字串流生成速度
  2. 自主偵測行為缺陷並主動修正錯誤
  3. 能夠自動產生出全新的後端程式碼
  4. 繞過底層安全機制以獲取最高權限
💡 後設認知讓代理人能「思考自己的思考過程」，進而達到修正錯誤與適應環境。
chap-m5-ch1
在代理人的推理迴圈中，「Action (行動)」階段的主要作用是？
#7123
  1. 分析使用者輸入文字背後隱藏的真實意圖
  2. 實際呼叫外部工具或 API 來改變環境狀態
  3. 觀察並記錄環境在指令執行後的回傳結果
  4. 評估自身表現的優劣並將其寫入錯誤日誌
💡 行動階段是指模型決定好策略後，具體執行工具呼叫來影響外部世界。

在代理人的推理迴圈中，「Observation (觀察)」階段的主要作用是？
#7124
  1. 獲取並解析外部工具執行後所回傳的具體結果
  2. 決定下一步應該要呼叫哪一個外部系統的工具
  3. 生成給使用者的最終自然語言對話回覆內容
  4. 將整次對話的完整歷史記錄壓縮備份到雲端
💡 觀察階段讓代理人能看到剛才行動的結果，作為後續判斷與推理的依據。

代理人類型

「Agentic RAG」與「Naive RAG」的主要差異是什麼？
#7106
  1. Agentic RAG 不使用向量資料庫
  2. Agentic RAG 只能處理文字資料，而 Naive RAG 可處理多模態資料
  3. Agentic RAG 讓代理人主動決定何時和如何進行檢索，可進行多輪查詢
  4. Agentic RAG 的回應速度比 Naive RAG 更快
💡 Agentic RAG 將 RAG 融入代理迴圈，代理人能自主判斷何時需要檢索、使用哪種查詢策略，並可多輪迭代查詢以獲得更完整的資訊。
chap-m5-ch1 sec-agent-types
Agentic RAG 與傳統的 Naive RAG 最大的區別在於什麼？
#7118
  1. 向量資料庫能容納的整體資料容量大小
  2. 代理人是否能主動決定何時進行資料檢索
  3. 伺服器回傳檢索結果的速度快慢差異
  4. 系統底層是否依賴強大的向量嵌入模型
💡 Agentic RAG 允許代理人根據當下需求，自主判斷是否需要呼叫檢索工具。
chap-m5-ch1
在多代理 (Multi-Agent) 系統中，不同的代理人通常是如何進行協作的？
#7126
  1. 所有代理人共用同一個神經網路模型與內部權重
  2. 代理人透過標準化協議交換訊息以分配並完成任務
  3. 代理人之間互相競爭搶奪系統中有限的運算資源
  4. 代理人會透過直接覆寫對方的短期記憶來傳遞資訊
💡 多代理系統透過定義明確的通訊協議，讓各自專業的代理人能分工協作。

Agent 的評估指標

評估 AI 代理人效能時，「步驟效率 (Step Efficiency)」指的是什麼？
#7107
  1. 代理人每秒能處理的請求數量
  2. 代理人完成任務所需的最少步驟數，步驟越少效率越高
  3. 代理人正確選擇工具的比例
  4. 代理人在給定時間內完成任務的比例
💡 步驟效率衡量代理人解決問題的簡潔程度，不必要的冗餘步驟會降低效率並增加成本和延遲。
chap-m5-ch1 sec-agent-eval
在評估代理人表現時，「任務成功率」指的是什麼？
#7119
  1. 系統成功呼叫所有外部工具的總次數
  2. 代理人最終能順利完成給定目標的比例
  3. 代理人生成回覆時所使用的總文字數量
  4. 代理人運行單一任務所耗費的整體時間
💡 任務成功率是最直觀的指標，衡量代理人是否能實際解決使用者交付的問題。
chap-m5-ch1
評估代理人時，「工具準確度」主要是用來衡量什麼？
#7120
  1. 工具伺服器回應 API 請求的延遲時間
  2. 代理人在各種情境下選擇正確工具的比例
  3. 每個外部工具執行時消耗的雲端運算資源
  4. 外部系統所能支援處理的多國語言數量
💡 工具準確度關注代理人是否能在對的時機挑選並正確呼叫合適的工具。

模型上下文協議 (MCP)

MCP 簡介與設計動機

MCP (Model Context Protocol) 主要解決什麼問題？
#7201
  1. 提升大型語言模型的推理速度
  2. 解決 AI 模型與外部工具整合的碎片化問題，提供標準化協議
  3. 改善 LLM 的訓練效率
  4. 降低 AI 模型的幻覺（Hallucination）問題
💡 MCP 提供統一標準，讓 AI 系統與工具的整合從 M×N 個客製化整合簡化為 M+N 個標準實作，解決碎片化問題。
chap-m5-ch2 sec-mcp-intro
MCP (Model Context Protocol) 旨在解決 AI 生態系統中的哪一個痛點？
#7210
  1. 訓練最新大型語言模型的整體運算成本過於高昂
  2. AI 系統與各種外部資料源整合時的嚴重碎片化問題
  3. 本地端執行伺服器時的記憶體管理與分配效率太低
  4. 開發者在設計提示詞工程時面臨的語法難度過於複雜
💡 隨著工具與資料源激增，MCP 提供標準化協議來消弭 M×N 的客製化整合噩夢。
chap-m5-ch2
